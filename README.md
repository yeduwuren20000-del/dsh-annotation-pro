# dsh-annotation-pro

给 DeepSeek Harness 的对话加**段落锚定批注**：选中任意一条消息（AI 的回复，或你自己发出去的话）
里的一段文字，写下批注，批注会变成输入框里一个带编号的「注释 N」块，随下一条消息一起发出去。

纯本地存储，**不调用任何模型**，不改动会话内容本身。

## 功能

- **选中即批注**：在任意消息里选区，弹出批注输入框；`Ctrl / ⌘ + Enter` 直接添加，`Esc` 收起
- **自己说的话也能批注**：AI 回复和用户消息都算选区范围
- **一个编号走到底**：输入框芯片、行内标记、注释面板、发给模型的内容，用的都是**同一个编号**
- **行内序号标记**：被批注的段落右侧有同样的序号，悬停可见批注摘要，点开可编辑 / 删除
- **发送只带编号**：消息里出现的是「注释 3：你的批注」，不再把被批注的原文整段抄一遍
- **原文定位**：批注条目和序号标记都能把视图滚回被批注的段落
- **按会话落盘**：每个会话一个 JSON 文件，重开还在
- **独立保存**：批注可以只保存不发出去，随时再「添加到对话」
- **导出**：会话批注可导出 Markdown 或 JSON
- **二次元看板娘**：注释栏的编号旁蹲着一只 DeepSeek 娘，会慢慢呼吸，新增批注时跳一下

## 看板娘

注释栏的「注释 N」旁边就是那只 Q 版 DeepSeek 娘：靛蓝长发、白色荷叶边发带、蓝色蝴蝶结、
呆毛、垂眼和腮红，深蓝领结上镶一颗菱形宝石。

用的是**原图本身**，不是照着画的 SVG：176×176、构建时把白底 flood-fill 掉、导出 WebP 约 10 KB，
以 `data:` URI 内联在 bundle 里。

- 不发任何网络请求，也没有需要解析的资源路径，装到哪都长一样
- 深色 / 浅色主题共用一张图，白底已经透明，不靠外框遮
- 只有整体动效（呼吸 4.2s、加批注时跳一下），一张位图没有五官图层可以单独动
- `prefers-reduced-motion` 下全部关闭

早期版本是手绘 SVG，能眨眼、甩呆毛，但形状终究是"照着画的"；换成原图后形象一致，代价是少了
眨眼这类分部件动画。

## 安装

```bash
dsh plugin add "github:yeduwuren20000-del/dsh-annotation-pro"
```

然后把这个插件加进 profile 的 `dsh.profile.bundles`，**完全重启宿主**（插件列表只在启动时读一次）。

也可以本地链接安装：

```bash
dsh plugin add "link:/path/to/dsh-annotation-pro"
```

## 使用

1. 在任意一条消息里用鼠标选中一段文字（AI 的回复或你自己发的都可以）
2. 弹出框里写下批注（最多 24000 字符），点「添加到对话」
3. 输入框里出现「注释 1」芯片；输入框下方工具栏的「注释 1」入口点开可逐条编辑 / 移除
4. 正常发送消息，模型收到的是「注释 1：你的批注」

「仅保存」会把批注留在会话备注里，不插入输入框；之后可从「已保存注释」列表点「添加到对话」。

## 编号规则

一个会话里每个编号**只属于一条批注**：第一次添加时领号（`max(已有编号) + 1`），之后一直跟着它，
写进批注文件一起落盘。

- 删掉「注释 2」后，剩下的仍是「注释 1」「注释 3」——**不会**把 3 重排成 2
- 输入框芯片、行内标记、面板条目、发给模型的那行文字，四处永远是同一个数字
- 新会话从 1 开始

这样做的原因很实际：发送出去的文字里写着「注释 3」，如果界面上的 3 因为删了一条而变成了 2，
模型和你就对不上号了。

## 存储

```
$DSH_HOME/profiles/<profile>/.dsh-annotation-pro/<sessionId>.json
```

文件格式 `version: 2`，每条批注含 `id` / `selectedText` / `comment` / `anchor` / 时间戳。
删除对应文件即清空该会话的批注。

## 接口

宿主侧在 `/plugins/dsh-annotation-pro` 下注册了这些路由（仅接受本机来源，
`dsh-app:` 协议与 `127.0.0.1` / `localhost` / `[::1]` 之外一律拒绝）：

| 路由 | 方法 | 用途 |
|---|---|---|
| `/annotations` | `GET` | 读取该会话全部批注 |
| `/annotations` | `PUT` | 新增或更新一条（带 `id` 即更新） |
| `/annotations/delete` | `POST` | 删除一条 |
| `/export` | `GET` | 导出，`fmt=md` 或 `fmt=json` |

请求体上限 512 KB。

## 实现备注

编号是**批注自己的属性**，不是渲染时算出来的：`reference.label` 直接写成「注释 7」，
CSS 里没有 `counter-increment`。早期版本用计数器自动编号，看着更"一致"，但删一条就会整体前移，
和已经发出去的「注释 3」对不上。

### 视觉

配色分两层：**琥珀**表示「被批注的内容」（高亮、序号、引用条），**DeepSeek 蓝 `#4d6bfe`**
表示「操作和身份」（主按钮、聚焦环、选中气泡、看板娘）。两个色各管一件事，所以同时出现也不会打架。

动效统一走两条缓动：`--an-ease`（cubic-bezier(.16,1,.3,1)，收尾减速）用于位移和颜色，
`--an-spring`（cubic-bezier(.2,1.3,.4,1)，轻微回弹）用于面板出现、悬停抬升、按钮按压。

注释面板的展开用 `grid-template-rows: 0fr → 1fr` 过渡，不用测高度也不用 `height:auto` 动画，
收起时保留 DOM 并置 `inert`，所以动画两个方向都顺、键盘也不会 Tab 进看不见的按钮。

### 为什么滚动时不卡

批注高亮是**固定定位**的浮层，每帧都要知道原文矩形。0.2.0 里这一步是这么做的：
每条批注各自去全文档找一遍 ROW、沿着祖先链逐层 `getComputedStyle`、再用
`indexOf` 做一次全文搜索 —— 成本是「批注数 × 行数 × 文本长度」，长回复里滚一下就是几十毫秒。

0.2.1 换成三层缓存：

| 层 | 做法 | 效果 |
|---|---|---|
| 布局快照 | 每帧只做一次 `querySelectorAll` + `getBoundingClientRect` / `getComputedStyle`，按元素记忆化 | 样式调用数与批注数无关（12 条批注和 2 条一样是 5 次） |
| Range 复用 | 解析出的 DOM Range 直接留着用；Range 是**活的**，DOM 变了会自己跟着走 | 滚动时不再做任何全文搜索 |
| 视口过滤 | 只测量与视口相交的行 | 长会话里成本与「当前可见的批注数」成正比 |

另外把 `MutationObserver` / `ResizeObserver` / `scroll` 监听**只在挂载时建立一次**：
0.2.0 把这些依赖挂在 `state.draft`、`state.pending` 上，而这两个对象每次 store 更新都是新引用，
于是**每敲一个字**都要拆掉重建整个观察器树并重新 `querySelectorAll`。

选择文本也不再逐帧处理：拖动期间（`pointerdown` → `pointerup`）不响应 `selectionchange`，
只在一帧内读一次，避免长回复里拖选时掉帧。

## 回归自检

```bash
node verify-ui.cjs
```

检查样式层的关键不变量：编号 counter 存在且只用一次、chip 没被隐藏、旧占位逻辑已移除、
`var(--an-*)` 全部有声明、CSS 括号平衡，以及看板娘的 5 组关键帧**只动 transform**
（动了 `opacity` / `background` 之类的绘制属性就会掉帧，断言会红）。改完 UI 先跑它，
21 项全 PASS 再提交。

## 兼容性

编写的目标运行时是 DSH `0.2.x`（`@deepseek-ai/*` 0.2.0-rc.2 以上）。
`peerDependencies` 里写的是区间，0.1.7-rc.1 到 0.3.0-0 之间均可解析。

## 已知限制

- 锚定方式是**选中文本 + 偏移**，如果消息内容被重新生成，旧批注可能定位不到原文（批注本身不会丢）
- 发送时只带「注释 N」，不带被批注的原文；模型要靠对话里的标记去对应，跨会话引用会看不出指向
- 「注释 N」的标签依赖 DSH 输入框 chip 的 DOM 结构（`.reference` 里第一个 span 是图标、第二个是标签）；
  若上游改写该结构，会退化为显示 DSH 自己的图标 + 标签（不影响功能）
